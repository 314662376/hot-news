# 财经热点 · 行业检索

> 两个功能，一个脚本（纯标准库，零依赖）：
> 1. **时段热点** —— 自动扫描全市场，给出某时段（隔夜/上午/盘后）热度最高、影响最大的 3~5 条
> 2. **行业检索** —— 你主动搜「PCB」才跑，不搜就不采集
>
> 线上看板（**带搜索框，手机直接搜**）：https://314662376.github.io/hot-news/

---

## 零、网页上直接搜（推荐）

打开 https://314662376.github.io/hot-news/ ，顶部就是一个搜索框：

- 输入 `PCB` / `半导体` / `固态电池`… 按回车即可，**1 秒出结果**
- 下方有 12 个常用行业快捷标签，点一下就搜
- 可选时间范围（3/7/14/30/90 天）、条数（5~30）、排序（重要性 / 时间）
- 搜索结果按「重要性」排序，命中的关键词高亮

**原理**：东财站内搜索接口是 JSONP 且带 `Access-Control-Allow-Origin: *`，
所以整套打分逻辑（同义词扩展 → 相关性判定 → 事件聚类 → 打分）**全在浏览器里跑**，
不需要后端、不需要 token、不需要等 Actions。规则与 `hot_news.py` 完全一致。

> 网页搜索只覆盖东财站内文章；CLI 版本还会额外并入 5 个实时快讯源
> （那些接口没有 CORS 头，浏览器拿不到）。要更全就用 CLI 或 Actions。

## 一、核心思路：热度靠「跨源共振」，影响靠「可验证的关联」

大多数人做这件事会去抓热搜榜。**但热搜是可以买的**，而且财经大事件经常不在热搜上。
更稳的信号是：

> 同一件事，被 5 家里的几家报道了、报了几条。

一条只有一家在报的消息，和一条东财/同花顺/新浪/见闻同时置顶的消息，
价值差一个量级——**共振度是买不出来的**。

「影响」则尽量用客观量，而不是让模型猜情绪：

| 信号 | 来源 | 说明 |
|---|---|---|
| 硬核关键词权重 | 自建词典 | 降准/关税/立案/退市/重组… 分档给权 |
| 关联板块数 | 同花顺 tags | 影响的行业面 |
| 关联个股数 | 东财 `stockList` | 影响的个股面 |
| **关联标的实际涨跌幅** | 腾讯行情 | 最硬的证据：市场已经用脚投票了 |

```
Score = 0.55 × Heat_norm + 0.45 × Impact_norm

Heat   = 3.0×(跨源数-1) + 1.0×min(条数,8) + 0.12×min(互动量,50) + 1.5×金十重要标记
Impact = 2.0×关键词权重 + 0.8×min(板块数,4) + 0.6×min(个股数,3) + 市场实证项
```

两项各自归一化到 0~100 再加权，所以排名对参数不敏感。
**盘面综述类**（收评/晚报/公告集锦…）统一降权 25% 并置为「中性」——这类文章罗列一堆板块，
信息密度低。

## 二、功能一：时段热点

经验值是这 5 段，覆盖 A 股一天的信息节奏：

| 时段 | 时间 | 看什么 |
|---|---|---|
| **隔夜** | 15:00 → 08:30 | 美股盘中+盘后、外盘商品、汇率、隔夜政策 → **决定开盘情绪** |
| **早间** | 08:30 → 09:30 | 盘前公告、集合竞价前策略 |
| **上午盘中** | 09:30 → 11:30 | 盘中异动、实时消息 |
| **午后盘中** | 13:00 → 15:00 | 尾盘资金、突发 |
| **盘后** | 15:00 → 24:00 | 公告密集期、龙虎榜、复盘 |

```bash
python hot_news.py --start 15:00 --end 08:30 --top 5    # 隔夜
python hot_news.py --start 09:30 --end 11:30            # 上午盘中
python hot_news.py --window 8                           # 最近 8 小时滚动
```

> 边界已处理：凌晨问「15:00→08:30」会正确取到**昨天15:00 → 今天08:30**，
> 而不是算成未来窗口。

## 三、功能二：行业检索（主动触发）

**只在你想查的时候才跑，不参与定时采集。**

```bash
python hot_news.py --keyword PCB                        # 自动扩展同义词
python hot_news.py --keyword PCB --days 14 --top 10     # 拉长到 14 天
python hot_news.py --keyword 机器人 --sort time          # 按时间倒序看流水
python hot_news.py --keyword "覆铜板,CCL,IC载板"          # 多个词：以你给的为准，不再扩展
python hot_news.py --keyword PCB --no-live              # 只查站内历史，不补实时快讯
```

**单关键词会自动扩展同义词**（内置 14 个常见题材，见脚本里的 `SECTOR_ALIAS`）：

```
$ python hot_news.py --keyword PCB
[检索] PCB → 扩展为 8 个词：PCB、覆铜板、印制电路板、线路板、HDI、IC载板、CCL、铜箔
```

想完全自己控制，就用逗号传多个词，此时不再自动扩展。

### 相关性是怎么判的（决定搜索质量的关键）

搜索结果里混着大量噪声——「盘面综述」「公告集锦」这类文章会把几十家公司罗列一遍，
顺带提到某行业一句，就被普通的关键词匹配捞进来了。所以：

1. **关键词出现在标题里** → 相关（最硬信号）
2. 标题没命中，但属于**综述/集锦类** → **排除**
3. 标题没命中且非综述 → 要求关键词在正文累计出现 **≥3 次**（兼顾深度报道）

实测效果：PCB 检索从 92 条降到 40 条，Top5 全是真正的产业链新闻
（覆铜板业绩预增、PCB 设计平台合作、铜箔产销量…）。

### 排序

- `--sort hot`（默认）：按重要性打分
- `--sort time`：按时间倒序，但**先按「标题是否命中关键词」分档**，
  避免一个只在正文提了两句的旧闻冒到最前面

## 四、数据源（全部免费、免签名，实测可用）

| 源 | 端点 | 独有价值 | 实测 |
|---|---|---|---|
| 东财 7x24 | `np-listapi.eastmoney.com` | **带关联个股代码**、评论数 | ✅ 稳 |
| 同花顺 7x24 | `news.10jqka.com.cn` | **带板块标签** | ✅ 稳 |
| 新浪 7x24 | `zhibo.sina.com.cn` | 补充覆盖面 | ✅ 稳 |
| 华尔街见闻 | `api-one.wallstcn.com` | **带评论数**（讨论热度） | ✅ 稳 |
| 金十快讯 | `flash-api.jin10.com` | **带官方 important 标记** | ✅ 稳 |
| 东财站内搜索 | `search-api-web.eastmoney.com` | **行业检索主源**，带媒体名+摘要 | ✅ 稳 |
| 腾讯行情 | `qt.gtimg.cn` | 代码 → 名称 + 涨跌幅 | ✅ 稳 |
| ~~东财行情~~ | `push2.eastmoney.com` | 板块名称 | ⚠️ 对机房 IP 随机拒连，已降级 |

### 踩过的坑（重要）

1. **东财行情接口 `push2.eastmoney.com` 会对机房 IP 随机断连**（`RemoteDisconnected`），
   且全部镜像域名（`1.push2` / `7.push2` / `82.push2` / `push2delay`）一样会被拒。
   腾讯 `qt.gtimg.cn` 完全正常，所以**主用腾讯、东财只用来补板块名**，失败就降级显示代码。
2. **不能逐条查行情**。500+ 个事件簇各查一次 = 500 次请求，直接把进程卡死
   （实测跑 4 分钟没结束）。必须「两段式」：
   先不带行情粗排 → 只解析头部簇的证券 → 再重排。
   请求量 ~600 降到 ~15，**25 秒 → 10 秒**。
3. **所有 HTTP 必须有界**：请求次数上限 + 连续失败熔断，
   否则一个挂掉的接口能把整个任务拖死。
4. **业绩公告标题高度模板化，会把不同公司误聚成一类**：
   「【德福科技：预计前三季度净利润…】」和「【平安电工：第三季度净利润…】」
   字符重合度极高。解法：抽出 `【】` 内的**主体**，主体不同则拒绝合并，
   再加**数字集合**二次约束。
5. **markdown 表格会被标题里的竖线撑破**，输出前统一替换为「丨」。

## 五、部署（GitHub Actions + Pages，零成本）

Actions 每交易日跑 3 次，结果提交进 `docs/` 并发布到 Pages：

| 北京时间 | 报告 |
|---|---|
| 08:35 | 隔夜报（15:00→08:30） |
| 12:05 | 上午盘中报（09:30→11:30） |
| 15:15 | 盘后报（13:00→15:00） |

**手动跑行业检索**：Actions → 财经热点·行业检索 → Run workflow → 填 `keyword`（如 `PCB`）。
填了就只跑检索，留空就跑时段热点。

看板首页 `docs/index.html` 会自动重建，按时间倒序列出所有报告。

## 六、已知限制 / 下一步

**限制**
- 关联标的的涨跌幅是**当前值**，不是新闻时点的值。对隔夜/凌晨窗口，
  A 股涨跌幅是上一交易日收盘价，有滞后 —— 所以市场实证项权重压得较低（最高 +2.5），
  只做方向确认，不主导排序。
- 行业检索的结果来自站内搜索，**没有 `stockList` 字段**，因此关联个股常为空；
  只有实时快讯补进来的那部分才有关联标的。
- 事件聚类是字符二元组的贪心聚类，对长文和跨语言（中英混排）效果一般。
- 板块名称依赖东财，被拒连时降级为 `BK0732` 这类原始代码。

**可选的增强**
1. **接 LLM 做二次研判**：把 Top 10 摘要丢给模型，输出「利好利空 + 影响板块 + 一句话影响」，
   比关键词表准得多，成本约几分钱一次。
2. **收藏行业定时监控**：目前检索是手动触发（按你的要求）。
   想改成每天自动盯几个行业，在 workflow 的 schedule 里加一行 `--keyword` 即可。
3. **加微博/雪球讨论量**：作为「讨论最多」的补充信号
   （微博热搜接口需 Cookie，建议走 RSSHub 自建）。
4. **和打板情绪看板联动**：当日 TOP 新闻和连板高度、封板率并排看，
   能看出「消息驱动」还是「情绪驱动」。
